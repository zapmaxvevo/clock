# Correcciones del slice 6 — revisiones

Salida de las seis revisiones sobre la rama `fase1/slice-6-masa` (`41ea0ca`). Seguridad,
backend y frontend aprueban; código, tests y paridad piden cambios. Hay un solo defecto de
conducta, que encontraron frontend, paridad y tests por separado: borrar en masa todas las
entradas desmonta la región, el foco cae a `body` y el resultado no se anuncia. Lo demás del
alcance se comporta en pantalla como dice el contrato. Se aceptan los tres desvíos de backend
y los siete de frontend, más el mecanismo de foco de `d0dccb6`. De los mutantes que backend
declaró equivalentes, se sostienen todos (E4, EQ1 a EQ4); el que no se sostiene es otro, el
orden de las comprobaciones (B1, B2, B12 de tests), que cae con una fila ajena que corre, como
en el slice 10: el código está bien y falta el test.

`RejectedError` dentro de la rama de `DomainError` (código m8 contra el desvío 1 de backend):
se queda como está. Backend y la revisión de backend muestran que el resultado es el que pide
el ADR 0011 y que la rama propia obliga a una aserción de tipos. El comentario de
`src/server/action.ts` nombra la equivalencia; el ADR no se toca.

El doble chequeo de permiso (action y service) lo pide el contrato y es el patrón de las doce
actions del módulo: no es un hallazgo de este slice.
